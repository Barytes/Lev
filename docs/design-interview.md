# Lev 设计访谈

更新日期：2026-09-29。本文区分用户已确定的需求与待讨论的设计建议；不是实现或运行验证记录。

## 已确定的需求

- 观察用户的电脑使用过程，识别意图，并主动提供协作。
- 优先使用实时事件流和结构化信息。视觉补充默认关闭，用户可针对指定应用开启；若验证表明这种方式不可行，则准备转向必要时自动补充截图的方案。
- 产品应具有广泛泛用性，不局限于特定业务场景。用户尚无确定的首个场景，要求结合其日常工作设计一至两个示例。
- 第一版平台为 macOS。
- 用户无需主动发起请求。遇到影响协助方向的歧义，可以主动提出简短问题，并同时提供选项与自由输入框。
- 观察采用前台跟随：开启后随用户切换应用持续观察，用户可以排除应用或随时暂停。
- 提示采用可调的分级制度，支持默认主动提示、仅重要内容主动提示和默认安静。用户要求能够开关或调整范围；范围具体指应用、任务还是内容类别，尚未确定。
- 协作级别采用“用户设上限，Lev 在上限内选择”的规则。L1 主动提出建议，用户可以选择某项后要求继续完成；L2 允许主动准备候选结果，也可以只提出建议或继续观察。允许准备结果不代表每次都必须生成产物。
- 提示偏好支持偏向问题或偏向机会，并允许在使用过程中实时调整。档位数量、具体阈值和“重要”的判定方法尚待确定。
- 允许主动读取当前工作直接关联的上下文（Q9 的 B），也允许主动搜索用户明确指定的可见资料范围（Q9 的 C）。C 的范围必须由用户指定。
- 提示偏好与主动协作的上限分别控制；当前已选协作方式为提出建议和准备结果。
- 默认保留近期操作证据并积累跨天工作记忆，用户可以开启长期活动历史。两类数据的具体保留时间尚未确定。
- 第一版本地采集、整理和存储数据，允许将为当前判断选出的上下文交给云端模型处理。具体模型与云端服务的数据处理设置尚未确定。
- 接入形式为桌面应用＋浏览器扩展。其他应用的专用适配按后续覆盖验证讨论。
- 实时节奏采用持续观察、关键变化后数秒内更新理解、复杂结果后台准备，并检查结果是否仍适用于用户的最新工作状态。2–5 秒是前述设计中的待验证目标，不是实测性能。
- 用户要求研究全双工架构的适用性；目前是研究与架构建议阶段，尚未确认采用特定运行时或模型。

## 建议的检验场景（待讨论）

下列场景根据此前讨论过的研究、写作和 Agent 产品开发活动设计。它们不是对用户当前实际操作的记录，也不代表这些应用的采集能力已验证。

### 场景一：把研究材料写进自己的方案

用户在浏览器阅读多智能体研究材料，摘录一段方法描述，再切到编辑器撰写实验方案。文档中出现“这个实验可以证明激励机制提升合作”的结论。

建议的观察输入：材料来源与可获取正文、选区、目标文档及其变化。观察与意图推断分别保存：摘录和新增文本属于观察；用户在设计实验属于可以修正的假设。

建议的协作：当当前结论缺少支撑时，在协作区呈现具体问题，例如“目前的设计同时改变了奖励与可用信息，结果难以归因于奖励；可以增加一个固定信息条件的对照”。建议附上依据，用户可以展开查看候选对照方案。

如果无法区分用户正在写背景综述还是实验设计，提供“背景综述 / 实验设计”和自由输入框来澄清。该澄清仅在它会改变协助内容时出现。

检验重点：是否理解当前产物和证据的关系，是否给出可以直接用于当前工作的内容。

### 场景二：在 Agent 项目开发中跟上执行反馈

用户让编码 Agent 修改一个功能，随后查看改动和测试输出，再打开官方文档。测试出现失败；在 Lev 分析期间，用户可能又修改配置并重新运行测试。

建议的观察输入：当前任务可获取的上下文、文件改动、具体测试输出、所打开的文档，以及后续运行结果。仅凭打开文档或多次切换窗口，不能确定用户遇到了故障。

建议的协作：根据具体失败和相关改动提供一个可核对的原因假设，以及最小修复候选或验证步骤。若新结果显示问题已经消失，撤回旧建议；若失败已变化，更新协作内容。

检验重点：是否理解操作后的结果，是否能够随着用户继续工作而更新或取消帮助。修复候选的生成方式、执行方式与授权范围仍待确定。

## 通用机制建议（未定稿）

跨场景维护以下信息：用户正在处理的对象、观察到的操作及结果、当前目标假设、可能值得协助的问题，以及建议所依据的状态。研究写作与开发调试是两种检验样本；长期应以新任务中的迁移表现检验泛用性。

结构化采集需要同时考虑操作与当前状态。用户已选定关联上下文读取与指定资料范围检索；这些范围的具体表达、应用接口覆盖及候选产物制作方式仍需展开。

## 当前待决问题

1. 评估是否采纳全双工研究提出的应用层并发运行机制；研究结论属于建议，尚未形成已接受的实现架构。
2. 确定用户继续工作时，后台任务如何继续、更新或取消，以及第一轮验证应证明什么。

后续分支包括首批实测应用与真实轨迹、提示与协作设置的作用范围、澄清的提示规则、资源预算、记忆保留与修正、候选产物的交付方式，以及泛用性和介入质量的验收。上述分支仍开放。

## 从视觉补充 B 转向 C 的验证建议（未执行）

B 已允许用户对指定应用开启视觉补充；C 的额外变化是由系统按需决定何时补充。因此，结构化采集出现缺口本身不足以判定 B 不可行。

建议按以下顺序定位失败：

1. 在选定的真实工作片段中，仅用结构化信息，核对工作对象、关键内容、操作结果与目标判断。
2. 对失败片段确认缺失的证据：若输入已有足够内容而判断错误，优先改进理解与协作逻辑；若采集器漏掉接口已暴露的信息，优先修复采集。
3. 若确实缺少画面信息，在对应应用已开启视觉补充的条件下比较判断结果。截图未改善的失败不构成增加截图的依据。
4. 若视觉补充有效，但按应用开启的方式频繁漏掉必要场景，或给用户造成持续的设置负担，再评估按需自动视觉补充 C。

具体工作样本、成功阈值、视觉触发规则和授权表现尚未确定。本轮仅完成设计记录，没有采集用户活动或验证任何运行能力。

## 建议的技术骨架（待验证）

本地观察源产生带来源的操作与状态记录，经上下文整理更新当前工作理解；模型按需要读取关联上下文和用户指定资料，形成可以修正的目标假设，并选择协作动作。工作记忆与活动历史分别管理；协作级别决定能主动准备什么，提示设置决定如何呈现。

候选观察源为 macOS 应用与窗口信息、无障碍接口、浏览器结构化页面信息和必要的应用适配。视觉补充是额外观察来源，不作为所有事件处理的前提。

实时节奏已确认分为本地观察、任务理解更新和候选结果生成三个层次：事件持续采集；关键变化后数秒内更新理解；复杂候选结果在后台准备，并在展示前检查是否仍适用于最新工作状态。测量起点、统计方法和负载条件仍需确定。

### 官方接口核查（2026-09-28，只读文档核查）

- [NSWorkspace 应用激活通知](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification)：可用于跟随前台应用切换，提供应用级信息。
- [AXObserverAddNotification](https://developer.apple.com/documentation/applicationservices/1462089-axobserveraddnotification)：通知订阅可能返回不支持错误；全系统无障碍对象本身不支持通知。需要逐应用、逐对象验证，且通知缺失与状态不可读应分开处理。
- [Chrome content scripts](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)：可读取页面 DOM；程序化注入受主机权限或临时 activeTab 权限约束。页面结构可读不代表网页应用的全部内部状态可读。
- [Apple WWDC23 ScreenCaptureKit Screenshot API](https://developer.apple.com/videos/play/wwdc2023/10136/)：可以根据过滤条件异步获取静态图像，视觉补充不必依赖连续视频流。

这些资料说明候选接口存在及其文档约束，不能证明 Lev 已具备采集、意图识别或实时协作能力。

### 全双工研究形成的架构建议（2026-09-29，待采纳）

完整的一手来源、机制说明、时间线与验证方案见 [全双工架构是否适合 Lev](./full-duplex-architecture-research.md)。

将全双工作为持续协作的交互目标，以持续观察、增量上下文、短时判断、可取消的后台工作和发布前有效性检查来实现。第一版不以采用或训练原生全双工模型为前提。

普通请求型模型调用按启动时的上下文快照处理；应用层持续接收事件不代表这些事件已进入正在运行的模型推理。新信息在后续调用、工具步骤间检查或必要的取消重启中纳入。

建议按具体工作对象和任务依赖判断新事件是否使结果失效。短暂切换应用和无关滚动不应导致所有任务取消；撤回授权、降低协作上限、任务依据失效等控制需要及时影响相关工作。取消是尽力停止，已失效的迟到结果还要在发布处拦截。

建议用相同模型、相同按时间释放的轨迹，对比顺序处理、并发但不检查结果有效性、并发且检查有效性的方案。分别测量新事件处理延迟、过时结果展示、错误取消、模型调用成本和用户认为有用的协作；离线轨迹无法证明真实用户收益，后者需要后续交互验证。

## 分级规则与具体建议

观察范围、提示模式和协作级别应分别控制。默认安静可以与准备结果同时开启；主动提示可以与仅提出建议同时开启。暂停观察与关闭主动提示的含义应清晰区分。

已确定的首版协作级别：

- 提出建议：分析已有上下文，给出具体发现与建议的下一步；不自行展开完整交付物的制作。
- 准备结果：可以制作供用户查看与采用的候选产物，例如草稿、对照方案或修改候选。读取范围与资源预算另行确定。

用户已确认设定协作上限，由 Lev 在其内选择提出建议或准备结果，并判断何时值得开始。允许准备结果不表示每次观察变化都必须生成一个产物。

提示偏好的建议档位为“偏重问题 / 均衡 / 偏重机会”。偏好用于调整筛选和排序，不意味着完全屏蔽另一类内容；这一具体语义尚待讨论。建议重要性综合具体证据、与当前工作的相关程度，以及现在介入的收益，不单由偏好决定。

关联上下文读取与指定范围检索均已确认。建议用文件、文件夹或用户选定的资料集合来表达可见资料范围，排除范围继续生效。云端推理已另行确认允许；任意互联网搜索的范围仍未确定。

建议设置调整后立即按新规则筛选尚未展示的内容；降低协作上限时，停止超出新上限的后台工作，保留已有候选结果供查看。调节偏好、关闭提示、暂停观察的具体运行语义仍待确定。
